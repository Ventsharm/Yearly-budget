# Yearly Budget — Google Apps Script reminder schedule

This is an **optional, free external clock** for the existing GitHub Actions/Firebase notification sender. It uses the same Firebase Spark project and the existing user-specific reminder logic. No Android rebuild, Firebase Cloud Functions, new secret versions, or new Firebase project.

The Apps Script code is in [google-apps-script.gs](./google-apps-script.gs). It is deliberately **public source without tokens**. Copy it into your own **private** Google Apps Script project; **never commit your token here**.

## Part A — Set up your private Google scheduler

1. **GitHub token:** Open https://github.com/settings/personal-access-tokens/new . Choose a **fine-grained** token. Resource owner: **Ventsharm**. Repository access: **Only selected repositories** > `Yearly-budget`. Repository permissions: **Actions — Read and write** (GitHub may also require Metadata — Read). Set a sensible expiration, and remember to renew it before expiry. Do not send the token through chat.
2. **Google project:** Open https://script.google.com/home/projects/create and create a private Apps Script project named **Yearly Budget Reminders**.
3. **Paste script:** Open [google-apps-script.gs](./google-apps-script.gs), copy its entire text, and replace the starter text in the Google Apps Script editor's `Code.gs`. Click **Save**. Do not add the token to the code.
4. **Save token privately:** In Google Apps Script select **Project Settings** (gear icon) > **Script properties** > **Add script property**. Name: `GITHUB_TOKEN`. Value: your new token. Save.
5. **Approve and check access:** Return to **Editor** and choose function `verifyGitHubAccess` from the function dropdown. Press **Run**, and follow the Google authorisation prompts for calling GitHub. The execution log should contain **GitHub access OK**. This step never contacts Firebase.
6. **Test an automatic live run:** Choose `scheduleOneTimeTest` and press **Run only once**. This only creates a Google timer, which automatically invokes `sendOneTimeTest` **at least two minutes later** (Google may delay execution). At that point it really requests your existing production reminder workflow, not a dry run. Do not manually run `sendOneTimeTest` for the unattended test.
7. **Verify:** Open https://github.com/Ventsharm/Yearly-budget/actions/workflows/daily-reminders.yml . Find a new run labelled **Reminders — apps-script-test** and inspect its logs. Confirm `event=workflow_dispatch`, `externalSource=apps-script-test`, `REMINDERS_DRY_RUN: false`, successful Firebase authentication, and **Daily reminder counts**. Only an eligible unclaimed reminder with a registered device can produce an FCM send, so `sent: 0` does not by itself mean the system failed. FCM acceptance does **not** guarantee a notification appeared on a phone.
8. **Install the daily schedule:** After verifying the test, choose `enableDailyAt930UK` and click **Run once**. Google will create **one daily clock trigger at approximately 9:30 AM UK time**, allowing about **15 minutes either way**. Timezone: `Europe/London`, automatically accounting for British Summer Time. Run `showSetupStatus` if you wish to see `dailyEnabled: true` (no secrets printed).
9. **Turn off the old GitHub timer:** Once the first external automatic run is verified, remove the remaining `schedule` section from `.github/workflows/daily-reminders.yml` while retaining `workflow_dispatch` and its inputs. Ask ChatGPT to do this GitHub edit after you've confirmed Step 7. This prevents two normal checks per day; the original cron is deliberately retained as a fallback until the switch is verified.

## Costs, safety and limitations

- **Normal one-a-day Firebase usage:** After the GitHub fallback cron is turned off, only the existing Firebase sender runs once each day. The Google scheduler itself makes **no Firebase reads or writes**. A **one-time live test does perform an additional** Firestore query and potentially delivery-claim writes/FCM calls.
- **Account-specific reminders:** No change to the existing `users/{uid}/yearlyReminders` and `users/{uid}/yearlyPushTokens` account isolation. The existing Firebase sender processes reminders due tomorrow and uses per-reminder delivery claims to avoid repeat sends.
- **Once-per-day control:** Apps Script stores the UK day of the last *accepted GitHub dispatch* in its private Script properties and uses a lock. This prevents two **Google-triggered** dispatch requests on the same UK day. It cannot stop a separately triggered GitHub cron, so that cron must be removed after verification.
- **Failures:** A successful Google Apps Script execution confirms GitHub accepted a dispatch, **not** that the GitHub job succeeded or the phone displayed the alert. Check Google Apps Script **Executions** and GitHub Actions. If a dispatch is accepted but the GitHub job fails, the Google scheduler intentionally does not retry that day (minimises Firebase usage but cannot guarantee delivery).
- **Approximate timing and limits:** Google time-driven triggers are best-effort and can be delayed or fail. `nearMinute(30)` allows approximately 9:15–9:45 UK, not precisely 9:30. A fine-grained token can expire or be revoked; replace its stored property when renewing.
- **Access safety:** Use a dedicated GitHub token restricted to this repository, and keep the Google script **private**; script editors could access its properties. No GitHub token belongs in your public code or Android app.
- **Rollback:** In the Google editor, run `disableDaily`; it removes only the Google daily clock. Your existing GitHub Actions workflow remains otherwise unchanged.
